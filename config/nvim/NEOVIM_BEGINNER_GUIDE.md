# Neovim 场景化新手指南

本文面向第一次把 Neovim 当作日常开发环境的用户，所有步骤都对应当前这套 LazyVim 配置。需要快速查键时打开 [Neovim / LazyVim 速查手册](./NEOVIM_CHEAT_SHEET.md)；本文重点解释在真实场景中何时使用这些能力。

Leader 是 `<Space>`。例如 `<leader>ff` 表示依次按空格、`f`、`f`，不是同时按下。

## 使用这份指南

不要从背完整快捷键表开始。建议按以下顺序学习：

1. 先掌握模式、移动、保存和退出，保证自己不会被困住。
2. 再练习“操作符 + 移动/文本对象”，这是 Vim 最可迁移的核心能力。
3. 然后加入文件搜索、LSP、Git 和测试，形成完整开发闭环。
4. 忘记按键时用 `<leader>?` 查看当前 Buffer 快捷键，或用 `<leader>sk` 搜索全部快捷键。

每次只挑两三个新动作，在当天真实工作中重复使用。比一次记住几十个按键更有效。

## 先建立五个心智模型

### 模式决定按键含义

| 模式 | 用途 | 常用进入方式 | 离开方式 |
| --- | --- | --- | --- |
| Normal | 移动、组合命令、调用工具 | 启动后默认进入 | 无需离开 |
| Insert | 输入文字 | `i`、`a`、`o` | `<Esc>` |
| Visual | 选择文字 | `v`、`V`、`<C-v>` | `<Esc>` |
| Command-line | 保存、替换、执行 Ex 命令 | `:` | `<Esc>` |
| Terminal | 与终端程序交互 | `<C-/>` 打开终端 | 再按 `<C-/>` 隐藏 |

拿不准当前模式时先按 `<Esc>`。本配置还会同时清除搜索高亮并停止活动中的代码片段。

### Vim 命令是一门组合语言

核心公式是：

```text
[次数] + 操作符 + 移动范围或文本对象
```

常用操作符：

| 操作符 | 含义 |
| --- | --- |
| `d` | delete，删除 |
| `c` | change，删除后进入 Insert |
| `y` | yank，复制 |
| `>` / `<` | 增加 / 减少缩进 |
| `g~` | 切换大小写 |

把它们与范围组合：

| 命令 | 拆解 | 结果 |
| --- | --- | --- |
| `dw` | delete + word motion | 删除到下一个单词 |
| `ciw` | change + inner word | 修改当前单词 |
| `di"` | delete + inside quotes | 删除双引号内部内容 |
| `yap` | yank + around paragraph | 复制整个段落 |
| `3dd` | 3 + delete line | 删除三行 |

不要把 `ciw` 当成一个孤立快捷键背诵；理解组合后，你自然会得到 `yiw`、`diw`、`ci"`、`da(` 等大量命令。

### Buffer、Window、Tab 不是一回事

- Buffer 是已打开文件的内存内容，即使屏幕上暂时看不到也可能仍然存在。
- Window 是观察 Buffer 的视口；一个 Buffer 可以同时显示在多个 Window 中。
- Tab 是一组窗口布局，不是浏览器式文件标签。

因此，关闭文件通常用 `<leader>bd` 删除 Buffer；关闭分屏用 `<leader>wd`；切换文件用 `<leader>,`，不必频繁操作 Tab。

### 项目根目录与当前目录不同

这套配置优先围绕项目根目录工作：

- 小写结尾通常使用项目根目录，例如 `<leader>ff`、`<leader>sg`。
- 大写结尾通常使用当前工作目录，例如 `<leader>fF`、`<leader>sG`。

在 monorepo 的某个子目录工作时，这个区别尤其重要。

### 先执行动作，再考虑插件名字

日常只需要记住“查文件”“看引用”“运行最近测试”。不需要先理解 Snacks、Trouble、Conform、Neotest 等插件内部结构。插件管理和排障放到最后。

## 场景一：第一次打开项目并安全退出

在终端中从项目根目录启动：

```sh
cd path/to/project
nvim .
```

完成一次最小工作流：

1. 按 `<leader><space>` 搜索文件，输入文件名的一部分并回车。
2. 按 `i` 进入 Insert 模式并修改内容。
3. 按 `<Esc>` 回到 Normal 模式。
4. 按 `<C-s>` 保存。
5. 按 `<leader>bd` 关闭当前 Buffer，或按 `<leader>qq` 退出全部。

需要传统命令时：

| 命令 | 含义 |
| --- | --- |
| `:w` | 保存 |
| `:q` | 退出当前窗口 |
| `:wq` | 保存并退出 |
| `:q!` | 放弃当前未保存修改并退出 |
| `:qa` | 退出全部 |

`q!` 会丢弃未保存内容，只在明确不需要这些修改时使用。

## 场景二：阅读代码并快速移动

先用结构化移动代替连续按方向键：

| 目标 | 命令 |
| --- | --- |
| 左 / 下 / 上 / 右 | `h` / `j` / `k` / `l` |
| 下一个 / 上一个单词 | `w` / `b` |
| 单词末尾 | `e` |
| 行首 / 第一个非空字符 / 行尾 | `0` / `^` / `$` |
| 文件开头 / 结尾 | `gg` / `G` |
| 跳到第 42 行 | `42G` 或 `:42` |
| 配对括号 | `%` |
| 当前行下一个字符 `x` | `fx` |
| 当前行跳到字符 `x` 前 | `tx` |
| 重复 / 反向重复字符查找 | `;` / `,` |

跨屏幕寻找目标时按 `s`，再输入目标处的两个字符。这是当前配置的 Flash 跳转，通常比反复使用 `w` 或搜索更快。

阅读定义链时形成以下节奏：

1. `gd` 跳到定义。
2. `gr` 查看所有引用。
3. `gI` 看实现，`gy` 看类型定义。
4. `K` 查看文档，`gK` 查看函数签名。
5. `<C-o>` 返回上一个跳转位置，`<C-i>` 再向前。

可以用 `ma` 在当前位置设置标记 `a`，稍后用 `'a` 返回。标记适合保存一个你会频繁返回的临时阅读位置。

## 场景三：不依赖鼠标完成精确修改

### 在正确位置开始输入

| 命令 | 进入 Insert 的位置 |
| --- | --- |
| `i` / `a` | 光标前 / 后 |
| `I` / `A` | 行首 / 行尾 |
| `o` / `O` | 下方 / 上方新建一行 |
| `s` | 本配置中用于 Flash，不是 Vim 原生 substitute |

由于 `s` 被 Flash 使用，想删除一个字符并进入 Insert 时用 `cl`。

### 修改一段已有代码

假设光标位于：

```text
const oldName = "temporary value";
```

可以这样操作：

- 光标在 `oldName` 上按 `ciw`，输入新名称，再按 `<Esc>`。
- 光标在引号内按 `ci"`，只替换字符串内容。
- 按 `A` 直接在行尾追加内容。
- 按 `dd` 删除整行，按 `p` 在下一行粘贴。
- 按 `yy` 复制整行，再用 `p` 粘贴副本。

完成一次修改后，按 `.` 可以在另一处重复“上一次修改”。例如先用 `ciw` 改一个单词，再移动到下一个同类位置按 `.`。

### 撤销、重做和寄存器

| 目标 | 命令 |
| --- | --- |
| 撤销 | `u` |
| 重做 | `<C-r>` |
| 重复上一次修改 | `.` |
| 查看寄存器 | `:registers` |
| 粘贴最近一次 yank | `"0p` |
| 删除但不污染默认寄存器 | `"_d{motion}` |

本配置使用系统剪贴板，普通 `y`/`p` 会与系统剪贴板协作。需要明确指定时仍可使用 `"+y` 和 `"+p`。

## 场景四：选择、移动、注释和包裹代码

选择方式：

- `v` 按字符选择。
- `V` 按整行选择。
- `<C-v>` 做块选择，适合同时编辑多行相同列。
- `<C-Space>` 按语法结构逐步扩展选择。

选中后可以直接接操作符，如 `d` 删除、`y` 复制、`>` 缩进。Visual 模式下连续按 `>` 或 `<` 时，本配置会保留选区。

处理整行或选区：

| 目标 | 命令 |
| --- | --- |
| 注释当前行 | `gcc` |
| 注释一个范围 | `gc{motion}` |
| 注释 Visual 选区 | 选中后按 `gc` |
| 上下移动行或选区 | `<A-j>` / `<A-k>` |

修改引号和括号时不要手动删两端：

| 目标 | 命令 |
| --- | --- |
| 给当前单词加双引号 | `ysiw"` |
| 给整行加括号 | `yss)` |
| 删除双引号 | `ds"` |
| 双引号改成单引号 | `cs"'` |
| 包裹 Visual 选区 | 选中后按 `S}` |

## 场景五：从当前文件搜索到整个项目

### 当前文件内搜索

| 目标 | 命令 |
| --- | --- |
| 向前搜索 | `/pattern` |
| 下一个 / 上一个结果 | `n` / `N` |
| 搜索光标下单词 | `*` |
| 反向搜索光标下单词 | `#` |
| 清除搜索高亮 | `<Esc>` |

只修改当前文件时使用替换命令：

```vim
:%s/old/new/gc
```

`%` 表示整个文件，`g` 表示每行全部匹配，`c` 表示逐项确认。新手建议保留 `c`，避免一次误改整个文件。

Visual 选中若干行后输入 `:s/old/new/gc`，Neovim 会自动把范围限制在选区。

### 项目范围搜索

| 目标 | 快捷键 |
| --- | --- |
| 项目全文搜索 | `<leader>sg` 或 `<leader>/` |
| 搜索当前单词或选区 | `<leader>sw` |
| 只搜索已打开 Buffer | `<leader>sB` |
| 当前目录全文搜索 | `<leader>sG` |

典型排查流程：先把光标放在函数名上按 `<leader>sw`，在结果列表中预览上下文，再回车打开目标。打开多个结果后用 `<C-o>` 沿跳转历史返回。

## 场景六：在大项目中管理文件、Buffer 和窗口

### 找文件而不是展开目录树

| 目标 | 快捷键 |
| --- | --- |
| 项目文件 | `<leader><space>` / `<leader>ff` |
| Git 跟踪文件 | `<leader>fg` |
| 最近文件 | `<leader>fr` |
| 项目树 | `<leader>e` |
| 复制当前文件相对路径 | `<leader>fy` |

知道文件名时优先用文件搜索；需要理解目录结构、创建或重命名文件时再打开 Neo-tree。

Neo-tree 中用 `a` 新建、`r` 重命名、`d` 删除，`s`/`v` 分屏打开，`P` 浮动预览，`H` 显示隐藏文件。执行删除前确认选中的确切节点。

### 管理已经打开的文件

| 目标 | 快捷键 |
| --- | --- |
| Buffer 选择器 | `<leader>,` |
| 上一个 / 下一个 Buffer | `[b` / `]b` |
| 最近两个 Buffer 间切换 | `<leader>bb` |
| 关闭当前 Buffer | `<leader>bd` |
| 关闭不可见 Buffer | `<leader>bi` |

### 同时对照两个文件

1. 用 `<leader>-` 水平分屏，或 `<leader>\|` 垂直分屏。
2. 用 `<C-h/j/k/l>` 在窗口间移动。
3. 用 `<leader><space>` 在当前窗口打开另一个文件。
4. 用 `<leader>wm` 临时最大化当前窗口，再按一次恢复。
5. 用 `<leader>wd` 关闭当前窗口。

窗口太窄时用 `<C-Left>` / `<C-Right>` 调整宽度，用 `<C-Up>` / `<C-Down>` 调整高度。

## 场景七：使用补全、LSP 和重构完成一次功能修改

输入代码时，补全菜单会自动出现：

| 目标 | 快捷键 |
| --- | --- |
| 下一个 / 上一个候选 | `<C-n>` / `<C-p>` |
| 接受当前候选 | `<CR>` |
| 选择并接受第一个候选 | `<C-y>` |
| 显示签名帮助 | Insert 模式 `<C-k>` |
| 跳到下一个代码片段位置 | `<Tab>` |

一次常见重构流程：

1. 用 `gd` 确认符号定义，用 `gr` 检查影响范围。
2. 按 `<leader>cr` 做语义重命名，不要用文本替换冒充重构。
3. 在报错或警告位置按 `<leader>ca` 查看 Code Action。
4. 按 `<leader>co` 整理导入。
5. 按 `<leader>cf` 格式化当前 Buffer 或 Visual 选区。
6. 按 `<leader>cd` 检查光标处诊断，再运行相关测试。

LSP 快捷键只会在当前语言服务器支持对应能力时出现。按 `<leader>?` 可以查看当前 Buffer 实际拥有的动作。

语言专属入口：

- Python 使用 `<leader>cv` 选择虚拟环境；pytest 会优先使用激活的环境、`.venv` 或 `venv`。
- Rust 使用 `<leader>cR` 调用 Rust Code Action。
- TypeScript/JavaScript 会在项目存在 ESLint 配置时启用 ESLint，并使用 Prettier 格式化。
- C/C++ 使用 `<leader>ch` 切换头文件和源文件。

## 场景八：定位并修复诊断问题

| 目标 | 快捷键 |
| --- | --- |
| 下一个 / 上一个诊断 | `]d` / `[d` |
| 下一个 / 上一个错误 | `]e` / `[e` |
| 下一个 / 上一个警告 | `]w` / `[w` |
| 当前行诊断详情 | `<leader>cd` |
| 工作区诊断列表 | `<leader>xx` |
| 当前 Buffer 诊断列表 | `<leader>xX` |

推荐修复循环：

1. 打开 `<leader>xx` 获取全局视图。
2. 用 `]e` 优先处理错误，用 `]w` 处理警告。
3. 在问题位置看 `<leader>cd`，再尝试 `<leader>ca`。
4. 格式化并保存，然后重新运行测试。

Trouble 或 Quickfix 列表打开后，可以用 `[q` / `]q` 在条目间跳转。不要把“列表中的问题”与“当前文件未保存的语法错误”混为一谈，先 `<C-s>` 再判断结果是否仍然存在。

## 场景九：审阅和提交 Git 变更

先在文件中逐个审阅 hunk：

| 目标 | 快捷键 |
| --- | --- |
| 上一个 / 下一个 hunk | `[h` / `]h` |
| 行内预览 hunk | `<leader>ghp` |
| Stage 当前 hunk | `<leader>ghs` |
| 撤销 Stage 当前 hunk | `<leader>ghu` |
| Reset 当前 hunk | `<leader>ghr` |
| 查看当前行 blame | `<leader>ghb` |

`<leader>ghr` 会丢弃当前 hunk 的工作区修改。新手应先用 `<leader>ghp` 预览，并优先在 Git 工具中确认后再执行 reset。

项目级入口：

| 目标 | 快捷键 |
| --- | --- |
| 打开 Lazygit | `<leader>gg` |
| 查看 Git 状态 | `<leader>gs` |
| 当前文件历史 | `<leader>gf` |
| 当前行历史 | `<leader>gb` |
| 项目 Git 日志 | `<leader>gl` |

一个稳妥的提交前流程是：保存全部修改 → `<leader>gs` 检查文件 → `[h`/`]h` 审阅 hunk → 运行测试 → `<leader>gg` 完成 stage 和 commit。

## 场景十：运行测试并分析失败

当前配置支持 Python、Jest、Vitest 和 Rust 测试。

| 目标 | 快捷键 |
| --- | --- |
| 运行离光标最近的测试 | `<leader>tr` |
| 运行当前文件 | `<leader>tt` |
| 运行全部测试文件 | `<leader>tT` |
| 重跑上一次 | `<leader>tl` |
| 打开测试摘要 | `<leader>ts` |
| 查看当前测试输出 | `<leader>to` |
| 打开输出面板 | `<leader>tO` |
| 停止测试 | `<leader>tS` |
| Watch 当前文件 | `<leader>tw` |

测试驱动的节奏：

1. 把光标放在测试内部，按 `<leader>tr`。
2. 失败时按 `<leader>to` 看完整输出。
3. 修改代码后按 `<leader>tl` 重跑相同测试。
4. 局部通过后按 `<leader>tt` 跑当前文件，最后再运行全量测试。

这套配置没有启用 DAP 调试器。需要调试时优先使用测试输出、日志、LSP 和终端中的语言原生调试工具。

## 场景十一：在不离开编辑器的情况下使用终端

按 `<C-/>` 打开项目根目录的浮动终端，再按一次隐藏。适合执行：

```sh
git status
rg 'pattern'
npm test
pytest
cargo test
```

终端是补充，不要用它替代已有的结构化能力：查文件优先 `<leader>ff`，查引用优先 `gr`，运行局部测试优先 `<leader>tr`。

需要当前工作目录而不是项目根目录时使用 `<leader>fT`；需要根目录终端也可以使用 `<leader>ft`。

## 场景十二：编写 Markdown 和技术文档

Markdown Buffer 会自动启用软换行、英文拼写检查和渲染。

| 目标 | 快捷键或命令 |
| --- | --- |
| Markdown 预览 | `<leader>cp` |
| 把单词加入拼写白名单 | `zg` |
| 标记单词为错误 | `zw` |
| 切换拼写检查 | `<leader>us` |
| 切换软换行 | `<leader>uw` |
| 格式化文档 | `<leader>cf` |

写完文档后先保存，再运行格式化和 Markdown lint。渲染结果正常不代表源文件一定通过 lint。

## 场景十三：批量处理重复修改

先尝试 `.` 重复。如果每次修改包含多个移动和编辑动作，再使用宏：

1. 按 `qa` 开始录制到寄存器 `a`。
2. 完成一次完整修改，确保光标停在便于处理下一项的位置。
3. 按 `q` 停止录制。
4. 按 `@a` 回放，按 `@@` 再次回放。
5. 确认安全后用 `10@a` 重复十次。

宏会忠实重放错误操作。先在两三处小范围验证，再增加次数；遇到异常立即按 `<Esc>`，然后用 `u` 撤销。

多个搜索结果需要逐项人工处理时，可以把结果放进 Quickfix，使用 `]q` 跳到下一项，修改后按 `.` 或 `@a` 重复。这比盲目的全局替换更适合结构不完全一致的代码。

## 场景十四：出错时恢复和排障

### 编辑操作失误

| 情况 | 处理方式 |
| --- | --- |
| 进入了陌生模式 | 连按一到两次 `<Esc>` |
| 刚才的修改错误 | `u` |
| 撤销过头 | `<C-r>` |
| 想放弃当前文件未保存修改 | `:edit!`，确认后执行 |
| 想查看较早状态 | `:earlier 5m`，返回五分钟前 |
| 想回到较新状态 | `:later 5m` |

### 开发能力没有生效

按以下顺序排查：

1. `<leader>?` 确认当前 Buffer 是否有目标快捷键。
2. `:LspInfo` 或 `<leader>cl` 检查语言服务器。
3. `:ConformInfo` 检查当前格式化器。
4. `:Mason` 检查外部语言工具。
5. `:Lazy` 检查插件状态。
6. `:messages` 查看最近错误。
7. `:checkhealth` 做完整健康检查。

如果只有某个项目异常，优先检查项目根目录、虚拟环境和项目配置文件，而不是立即修改全局 Neovim 配置。

## 七天练习路线

### 第一天：不被模式困住

- 只练 `i`、`a`、`o`、`<Esc>`、`u`、`<C-r>`、`<C-s>`。
- 用 `h/j/k/l` 完成短距离移动。
- 完成一次打开文件、修改、保存、退出。

### 第二天：学习 Vim 语法

- 强制使用 `ciw`、`diw`、`ci"`、`dap`。
- 每完成一次修改，思考能否用 `.` 重复。
- 尝试给命令加次数，如 `3j`、`2dw`、`5dd`。

### 第三天：摆脱目录树依赖

- 用 `<leader>ff` 查文件，用 `<leader>sg` 查内容。
- 用 `<leader>,` 和 `[b`/`]b` 管理 Buffer。
- 只在创建、删除或理解结构时使用 `<leader>e`。

### 第四天：建立代码阅读路径

- 使用 `gd`、`gr`、`gI`、`K`。
- 每次跳转后用 `<C-o>` 返回。
- 尝试用 `s` 替代五次以上的 `w` 或方向键移动。

### 第五天：完成一次安全重构

- 用 `<leader>cr` 重命名符号。
- 用 `<leader>ca` 处理一个诊断。
- 用 `<leader>cf` 格式化，再用 `<leader>co` 整理导入。

### 第六天：把测试和 Git 接入循环

- 用 `<leader>tr`、`<leader>tl` 形成快速测试反馈。
- 用 `[h`/`]h` 和 `<leader>ghp` 审阅修改。
- 提交前用 `<leader>gs` 或 `<leader>gg` 查看完整状态。

### 第七天：自动化重复劳动

- 找一个可用 `.` 重复的真实修改。
- 录制并安全回放一个宏。
- 用 `<leader>sk` 搜索一个你尚未记住的动作。

## 达到熟练的判断标准

当你能稳定做到以下事情，就已经跨过新手阶段：

- 很少因为模式混乱而中断操作。
- 能从操作符、移动和文本对象组合出新命令。
- 能区分搜索文件、搜索文本、查找引用和诊断列表。
- 能解释 Buffer 与 Window 的区别，并快速切换或分屏。
- 能独立完成“定位代码 → 修改 → 格式化 → 测试 → 审阅 Git hunk”的闭环。
- 遇到未知能力时会用 `<leader>?`、`<leader>sk` 和 `:checkhealth` 自助排查。

继续提升时，不要追求更多插件，优先增加对 `:help motion.txt`、`:help text-objects`、`:help registers`、`:help quickfix` 和 `:help recording` 的理解。
